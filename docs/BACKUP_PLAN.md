# 백업 계획 (제안)

2026-11-17 점검의 H5(백업 없음)에 대한 제안이다.
배포 방식을 정할 때 함께 확정한다. 아직 구현하지 않았다.

## 무엇을

- DB: 인허가 대장, 의무사항, 기한, 일정, 계정.
- 문서 저장소(S3 버킷): 증빙·원문 PDF.
- 둘 중 하나만 있으면 복구가 안 된다. 같은 시각 기준으로 함께 남긴다.

## 어떻게

1. 매일 새벽(예: 03:00 KST) `pg_dump -Fc`로 DB를 덤프한다.
2. 같은 시각에 문서 버킷을 다른 저장소로 복사한다(`aws s3 sync` 또는 `rclone sync`).
3. 덤프와 버킷 사본은 서버 밖(다른 디스크·클라우드 버킷)에 둔다. `docker compose down -v` 한 번에 같이 사라지면 안 된다.
4. 보관: 일간 14개, 월간 6개. 오래된 것은 지운다.
5. 백업 작업이 실패하면 회사 관리자에게 메일을 보낸다(기존 Mailer 재사용).

## 복구 리허설

- 월 1회, 빈 DB와 빈 버킷에 최신 백업을 복구한다.
- 복구한 스택에 로그인해 프로젝트 하나의 인허가·문서 다운로드가 되는지 본다.
- 걸린 시간과 문제를 기록한다.

## 정할 것

- 백업 보관 위치(클라우드 버킷, NAS 등)와 접근 키 관리.
- 덤프 암호화 여부(개인정보: 이름·이메일).
